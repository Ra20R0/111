# Рыбка от Светланы — магазин + админка

Витрина для клиентов (PWA, ставится ярлыком на рабочий стол, открывается по ссылке из группы WhatsApp)
и админ-панель для учёта остатков, броней, предзаказов, сборки и доставки.

## Запуск на компьютере

Нужен Node.js 20+.

**Проще всего:** двойной клик по `start.bat` — он сам найдёт Node.js, при первом запуске поставит зависимости,
запустит магазин и откроет браузер. Остановить — закрыть чёрное окно. Второй раз одновременно не запустится:
локальная база рассчитана на один процесс.

Вручную:

```bash
npm install
npm run dev
```

- Витрина: http://localhost:3000
- Админка: http://localhost:3000/admin — `admin` / `ryba2026`, курьер — `courier` / `dostavka2026`

База создаётся сама в `.data/pglite` и заполняется демо-каталогом по мотивам чата группы
(цены, кроме креветки по акции и Фри Элит, — примерные). Чтобы начать с нуля — удалите папку `.data`.

```bash
npm test         # 40 проверок: цены, брони, предзаказы, сборка, рейсы, прайс, отчёты, тексты для WhatsApp
npx tsc --noEmit # проверка типов
```

## Загрузка прайса из Excel

Админка → Excel → выбрать файл. Прайс «ИНФОРМАЦИЯ ОБ ОСТАТКАХ» (НАИМЕНОВАНИЕ | Свободные в наличии | Цена за… | ЦЕНА | | АКЦИИ)
распознаётся автоматически: фасовка, цена за 100 г, «1 рыбка / 4 шт.» у весовой рыбы, акции и новинки в названии,
разделы. Перед загрузкой показывается предпросмотр. Галочка «Заменить весь каталог» удаляет текущие товары, заказы и рейсы;
без неё обновятся цены и остатки у совпавших товаров. Сопоставление идёт по названию из прайса (`source_name`), поэтому
товар можно спокойно переименовать в админке — дубля не будет. Название, раздел, описание и оптовые цены из админки сохраняются.

В разделе «Товары» есть **проверка номенклатуры**: дубли, товары без цены и раздела, слова КАПСОМ, длинные названия,
подозрительная цена за кг, товары без фото.

## WhatsApp: как покупатели попадают в магазин

- **Превью ссылок.** У главной и у каждого товара есть картинка Open Graph (`opengraph-image.tsx`): WhatsApp показывает
  её прямо в чате — название, цену, наличие, фото. Шрифт Manrope с кириллицей лежит в `lib/fonts` (лицензия OFL).
- **Короткие ссылки:** `/t/123` — товар, `/c/5` — раздел, `/c/promo` — акции и новинки. Каталог понимает
  `/?c=5`, `/?q=сёмга`, `/?all=1` и при переходе по такой ссылке сразу показывает товары.
- **Админка → «Для группы»:** ссылка на магазин, готовые тексты закреплённого сообщения, описания группы и приветствия,
  ссылки на разделы. В «Товарах» кнопка 🔗 копирует ответ на «а есть …?» — название, цену, наличие и короткую ссылку.
- **Утренние остатки** (Админка → Остатки): ссылка на магазин первой строкой (по ней строится превью), у каждого
  раздела своя ссылка.
- В настройках можно указать ссылку-приглашение в группу — на странице «Инфо» появится «Вступить в группу».

## Документы и отчёты

Админка → Отчёты: выручка, средний чек, продажи по дням и товарам за период; выгрузки в Excel — заказы с позициями,
журнал движения товара, текущие остатки. В «Закуп и приход» — история приходов (поставщик, позиции, сумма закупа).

## Зависимости

`npm audit` — 0 уязвимостей. Через `overrides` в `package.json` подняты вложенные пакеты: `postcss` у Next 15
(уязвимость в 8.4.31; переход на Next 16 не нужен), `uuid` у exceljs и `esbuild` у drizzle-kit. После обновления Next
проверьте, нужны ли они ещё.

То же из командной строки (локальную базу — при остановленном `npm run dev`):

```bash
npx tsx scripts/preview-price-list.ts "Прайс.xlsx"            # посмотреть, как разберётся
npx tsx scripts/import-price-list.ts "Прайс.xlsx" --replace  # загрузить, заменив каталог
```

## Как устроено

| Что | Где |
| --- | --- |
| Схема базы | `db/schema.ts`, миграции — `drizzle/` |
| Цены, оптовые ступени, доставка | `lib/pricing.ts` |
| Брони, предзаказы, сборка, журнал остатков | `lib/stock.ts`, `lib/orders.ts` |
| Тексты для WhatsApp (заказ, чек, остатки) | `lib/whatsapp.ts` |
| Витрина | `app/(shop)/`, `components/shop/` |
| Админка | `app/admin/`, `components/admin/` |

Главные правила:

- **Свободно = остаток − в брони.** Бронь ставится атомарно: «последние 2 кг» достанутся только одному.
- Не хватает или товар «ожидается» → позиция уходит в **предзаказ**. При приходе (или когда остаток подняли
  вручную) предзаказы сами становятся бронями по очереди — кто раньше записался.
- **Сборка**: вводится фактический вес → склад списывается по факту, сумма пересчитывается, чек уходит клиенту
  через WhatsApp в один тап.
- Любая правка остатка пишется в журнал (видно в карточке товара).

## Выкладка в интернет (Netlify + Supabase)

Код — в приватном репозитории GitHub `B1t1ng/rybka-semey`; Netlify пересобирает сайт после каждого `git push`.

1. **Supabase** (supabase.com → войти через GitHub, бесплатный план):
   - New project: имя `rybka-semey`, регион **Central EU (Frankfurt)**, пароль базы — сохраните.
   - Storage → New bucket: `media`, включить **Public bucket**.
   - Заполнить `.env.deploy` (файл в git не попадает): кнопка **Connect → Session pooler** (порт 5432) →
     `DATABASE_URL` (вместо `[YOUR-PASSWORD]` — пароль базы); Project Settings → API → `SUPABASE_URL`
     и ключ `service_role` → `SUPABASE_SERVICE_ROLE_KEY`.
2. **База и данные** (локальный магазин при этом закрыт):
   ```bash
   npm run db:migrate
   npm run db:copy-to-prod
   ```
   Переносятся товары, остатки, клиенты, заказы, приходы, журнал и фото. Пользователи админки — нет.
3. **Пользователи админки** — пароль спросит и не покажет на экране (минимум 10 символов):
   ```bash
   npm run create-admin -- svetlana "Светлана" owner
   npm run create-admin -- artem "Артём" courier
   ```
4. **Netlify** (app.netlify.com → войти через GitHub; бесплатный план допускает коммерческое использование):
   Add new site → Import an existing project → GitHub → `rybka-semey`. Имя сайта `rybka-semey`.
   Environment variables (секретные отметить «Contains secret values»):
   - `NEXT_PUBLIC_SITE_URL` = `https://rybka-semey.netlify.app`
   - `SESSION_SECRET` = случайная строка (PowerShell:
     `$b=New-Object byte[] 32;[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b);($b|%{$_.ToString("x2")}) -join ""`)
   - `DATABASE_URL` = **Transaction pooler** (порт 6543) из Supabase → Connect
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_BUCKET` = `media`

   Site configuration → Functions → Region — выберите Европу (ближе к базе во Франкфурте), если доступно.
5. **Бэкапы**: GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret
   `SUPABASE_DB_URL` = строка Session pooler. Копия базы делается каждую ночь (Actions → «Бэкап базы»,
   хранится 30 дней); запустить вручную — кнопка Run workflow.
6. Админка → «Для группы»: отправить и закрепить сообщение со ссылкой, вставить текст в описание группы.

Если адрес сайта поменяется (другое имя на Netlify, свой домен) — исправьте `NEXT_PUBLIC_SITE_URL` в Netlify
и «Адрес сайта» в настройках админки.
